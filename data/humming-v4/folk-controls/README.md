# 固定 Folk 方新书负例输入

固定题号 q79 / q127 / q128 / q132，expected 均为方新书；来源依据 `data/manifest.json` 的 image_file 与 coarse_label。用途是检查轻吟修正规则是否把 Folk 误认成 Humming；本次仅准备输入，未运行匹配或读取新实验分数，不把题库标签宣称为字体文件的独立鉴定。

| 题号 | 阅读顺序去重后的固定字符 | 数量 | 极性/不足说明 |
| --- | --- | --- | --- |
| q79 | 屋根閉めます | 6 | 黑字；正文中的长音线ー及旁侧拟声不计常规字，因此不足7，不换题。 |
| q127 | ってどうしまた息荒いですけ | 13 | 黑字；原文右列ってどうしました、左列息荒いですけど，重复し、ど跳过。 |
| q128 | ヒビキさん今どこですかもう約 | 14 | 黑字；右列到左列，达到上限截止約。 |
| q132 | スケッチしてたんですよね | 12 | 黑字；正文右列スケッチしてた、左列んですよね；没有ら。 |

按阅读顺序取前最多14个不同可读常规字，保留小假名、浊点，排除标点、框线与旁注。没有白字样本。已人工逐张核对 `review/*-glyphs.png` 和 `review/*-source-bboxes.png`；q132 初标多出的一格实际是底框线，已在冻结前修正，旧草稿池与冗余裁片已移除，可由原图重新生成，不影响源图。

`annotations.json` 用 apply_patch 分两小批标注，再依据 review 修正。`build_expansion_pool.py` 采用绝对标注路径构建；`crops/` 保留源像素，不缩放、不反色、不二值化、不加粗。`review/` 是用于检查的放大/框选图，不作为匹配输入。`pools.json` 保存来源和裁片 SHA-256、原坐标 bbox、polarity、字符及质量字段；质量字段只评价输入图像，不是字体实验分数。

`freeze.json` 固定最终文件哈希及45字清单。复核命令（项目根执行，禁止生成目录外 pycache）：

```sh
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python data/humming-v4/folk-controls/verify_inputs.py
```

校验内容：固定题号/标签、manifest 来源、字符顺序及唯一性、原图/裁片哈希、裁片与原图 bbox 逐像素相同、无多余裁片、review 文件存在。冻结后重复运行只核对，不刷新 freeze。仅写入本目录，未修改其他文件。
