# 圆体、宋体、黑体：同字匹配基线 v1

## 用户确认的规则

- 圆、宋、黑先按大类识别，不把细／中／粗分得过细。字重仍参与模板搜索，因为粗细会影响视觉匹配，但不独立计算分类错误。
- 攸望黑体内的日文字形属于另一类黑体，纳入黑体候选。
- Antique AN+ 的假名具有宋体风格，属于正常字族设计；不能以此把它排除或改标为宋体。
- 少女、方圆、海报分别对应 RodinHappy L、B、UB，是单独的答案映射例外，不在本轮三类基线内。

## 已生成的材料

- 12 款字体：新丸ゴ 3 款、Ryumin 3 款、Antique AN+ 4 款、攸望黑体 2 款。
- 9 张清晰开发样本，每张 3 字，共 27 个裁片、26 个不同字符。字符由当前代理对照原图视觉核对，未做独立人工双审。
- 312 张 128px em 字体渲染模板；读取 cmap 验证每个所需字符确实存在，不使用系统字体回退。
- 字体清单包含内部名称、字重、文件指纹、来源相对路径及竖排相关表存在情况。这里的表检查不是完整竖排 shaping 验证。
- 每张截图有三行对照图：原图归一化字形，以及各大类中该字的最佳模板。图中显示内部字体名和距离，越小越接近。逐字最佳字体可不同；整题排名则要求三个字使用同一款字体。
- 原始裁片不覆盖；证据目录保留原图裁片和另存的归一化图，JSON 记录来源坐标和 SHA-256。

入口：

- `data/baseline_samples.json`：固定字符、来源裁片索引及分组规则。
- `data/baseline-v1/templates/catalog.json`：字体与模板索引。
- `data/baseline-v1/results.json`：完整逐字／整题字体排名和大类排名。
- `data/baseline-v1/evidence/`：原始裁片、归一化图、9 张对照图。

## 方法边界

这是先绕开 OCR 的同字匹配：已知字符 → 每款字体渲染同一字符 → 对齐与距离 → 多字汇总。

归一化保留长宽比例，不做独立横向拉伸、笔画膨胀或擦除。对源图与模板做 Otsu 二值化、等比例缩放；模板仅搜索 0.96／1／1.04 倍尺度和两个方向 ±2px 的位移。距离由 Dice 差异与双向距离变换组成。每款字体取三个字平均距离，各大类取其中最佳字体。

这些是 v1 的固定起始参数，没有针对本轮排错的题目改权重。候选数量不同可能带来最小值选择偏差，因此不把分数解释为概率。每个字的 kana／kanji 标记保留在 JSON，可追查混排字体在两种文字上的表现。

仅处理独立直立字符。没有假定已支持竖排标点替换、完整文本 shaping、反白／描边渲染、未知字符、字体缺库拒判或任意缩放失真。当前模板归一化不能模拟低分辨率截图的全部退化过程。

## 首轮结果

| 样本 | 题库归并类 | 排名第一 | 结果 |
|---|---|---|---|
| q115 | 圆体 | 圆体／新丸ゴ M | 一致 |
| q91 | 圆体 | 圆体／新丸ゴ L | 一致 |
| q100 | 圆体 | 圆体／新丸ゴ M | 一致，领先黑体距离很小 |
| q72 | 宋体 | 黑体／Antique AN+ U | 不一致 |
| q114 | 宋体 | 宋体／Ryumin B | 一致；不据此断言字重正确 |
| q92 | 宋体 | 黑体／Antique AN+ M | 不一致 |
| q125 | 黑体 | 黑体／Antique AN+ M | 一致 |
| q58 | 黑体 | 黑体／攸望 B | 一致 |
| q96 | 黑体 | 圆体／新丸ゴ B | 不一致 |

**6/9 是人工挑选开发样本的大类 Top-1 一致数，不是实际识别准确率。** 只有三类候选，不能由 Top-3 必含答案推导系统有用。题库答案也不是源日文字体文件的逐字认证。

视觉抽查 q72、q92、q125 的对照：源图与字体渲染有明显分辨率／笔画形态差异。q92 的宋体细节并未使当前距离函数优先选宋体。误差可能涉及二值化损失、当前评分对局部宋体特征不敏感、字体库与真实源字形不完全一致；尚不能确定各因素贡献，不能据此断言题库标错或字体文件错误。

## 验证与复现

使用已有 Pillow 运行时渲染，现有项目 venv 执行 OpenCV 匹配；未新增依赖、安装系统字体或修改字体文件。

```sh
# 在项目目录执行；也可替换为已有 Pillow 的 Python。
python3 -m mikan_font_probe.build_font_templates --output data/baseline-v1/templates
.venv/bin/python -m mikan_font_probe.match_font_baseline
.venv/bin/python -m unittest tests.test_adaptive_regions tests.test_typographic_regions tests.test_font_baseline -v
```

13 项测试通过；新加 4 项覆盖等比归一化且不修改输入、空白拒绝、自匹配优于不同形状、三类样本规则。三个新 Python 文件的语法编译通过。这些是代码行为验证，不是字体识别质量验收。

## 后续实验顺序

1. 保留 v1。建立更接近截图分辨率的渲染／降采样对照，区分二值化和分辨率造成的损失，不直接针对 q72、q92 调答案。
2. 用清晰匹配样本验证轮廓与端点细节等补充特征，再看宋体易混淆问题；限制形变，不能把错误字体随意改造成正确字体。
3. 增加未参与调参的截图，按图和来源去重划分验证。q33 与 q91 为高度相近内容，不能直接当独立训练／测试证据。
4. 最后接回自动切分与不确定读字，再评估整条链路。字重仍作为干扰变量；RodinHappy 三种答案后续独立验收。
